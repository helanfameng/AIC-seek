## 结果

| 输入到哪张 | 相对首次可见烟羽 | 阶段结果 | 报警 |
|---|---|---|---|
| 1～4 | 0～3分钟 | 当前检测设置下没有候选输出 | 否 |
| 5 | 4分钟 | 首次有框，但跨度和检测条目数不足，轨迹被过滤 | 否 |
| 6 | 5分钟 | 保留轨迹成立，概率0.6761826 | 否 |
| 7 | 6分钟 | 概率0.8387710，首次达到阈值 | 是 |
| 8～10 | 7～9分钟 | 持续达到阈值；末次0.9937540 | 是 |

这一序列首先受到首次候选产生较晚的限制，其后还需要形成轨迹及达到最终阈值。不能把检测到框等同于已经报警，也不能把概率当作准确率。

## 文件与解释边界

- `summary.csv`：每个前缀的汇总。
- `diagnostics.json`：实际配置、有效帧映射、原始候选、合并前轨迹及筛选条件、各次最终预测；保留运行时记录不修改。
- `visualization.html`：浏览器打开，黄框是阈值与NMS后的YOLO候选，绿框是保留轨迹，蓝框是实际分类裁剪。相同位置的框可能互相遮盖。
- `当前初始项目机制.md`：模型流程与框的含义。

`pre_merge_filter_failures`只描述合并前的长度/观测数条件，轨迹合并后ID不能直接一一对应。前4帧无候选输出不证明网络内部没有低于阈值的响应。各前缀的first_crossing_frame仍为null，因为没有开启上游内部触发搜索；首次报警来自独立运行完整前缀得到的首个阳性结果。

6分钟是采样时刻之差，未计计算和通信耗时；耗时与峰值显存未测。与训练数据是否重叠尚未核实；一个有烟事件不能说明误报率或泛化能力。尚未进行降阈值、高分辨率或无火序列对照。

下一步分别比较置信度0.05（分辨率仍1024）和分辨率1536（置信度仍0.1），结合额外错误候选、首次正确候选和首次报警评估，随后补充无火干扰数据。
