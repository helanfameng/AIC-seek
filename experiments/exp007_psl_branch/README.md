# 实验七分支：PSL思想的区域分类适配

状态（2026-10-24）：**正式三种子训练、验证校准、旧方法复评与修订诊断集评价均已完成**。六个新增方法分别训练42/43/44三个种子，共18个模型，各方法最终检出10/10。完整P5改善2019弱烟，但增加误报并拖慢部分场景，尚未证明综合优于原版。详见[完整分析](analysis_20261024/ANALYSIS_20261024.md)、[方法汇总](analysis_20261024/method_summary.csv)及[三种子正式结果](outputs/exp007_main_20261023/baseline/RESULTS_ALL_SEEDS.md)。方案日期2026-10-22，程序日期2026-10-23；这是PSL思想的区域适配，不称为原像素PSL完整复现。

直接运行见[完整启动命令](RUN.md)，冻结参数见[protocol.json](protocol.json)，实现差异见[METHODS.md](METHODS.md)。入口为`scripts/run_experiment.ps1`，默认复用实验六缓存，只提取两段新增序列。

## 1. 要回答的问题

在相同候选和冻结Pyronear特征下，使用多原型、BES与PUO的区域级适配，能否比普通分类头更稳定地区分烟雾与复杂背景，同时保留早期烟雾召回？

实验六中，学习残差比均值残差多出4段正常误报，且正常预测器在验证/测试上误差更大。这里直接测试判别表示学习的价值，不把“背景变化大”等同于有烟。该分支只重评分已有候选，无法解决ml-w左侧烟雾没有候选覆盖的问题。

综合问题和其他路线见[问题汇总](../../RESEARCH_ROADMAP.md)。

## 2. 与原始PSL的关系

作者的PSL是烟雾分割方法：以像素掩码监督，在特征空间建立每类多个原型，配合BottomK Eigenvalues Scatter（BES）损失与Prototype Uncorrelated Optimization（PUO）。作者代码还使用原型分配及专门的更新流程。普通监督对比学习不是其完整定义。[作者仓库](https://github.com/LujianYao/psl)、[核心代码](https://github.com/LujianYao/psl/blob/main/mmseg/models/decode_heads/PSL_main.py)、[配置](https://github.com/LujianYao/psl/blob/main/config/psl_config.py)

本分支第一阶段保留现有冻结编码器，用候选级真假标签训练小投影与分类模块。改变了监督粒度、主干训练方式和输入分布，因此统一称为**PSL思想的区域适配**。完整像素级PSL复现留待掩码数据准备后另行登记，不用候选标签伪装像素真值。

作者环境为Linux/Python 3.8/PyTorch 1.8/MMCV体系；不能直接假定兼容本项目Windows/Python 3.12/PyTorch 2.7。第一阶段提取方法逻辑并编写小模块，不将整套旧分割框架混装到现有环境。BES/PUO数值稳定性及原型更新的实现差异必须单独记录。

## 3. 固定项与输入

- 固定官方模型、检测器、关联、候选裁剪和DINOv2权重。当前DINOv2来自官方任务模型，不称为未经任务适配的通用编码器。
- 第一阶段复用经指纹核验的实验六缓存；对所有新头使用同一批候选、标签、样本权重、基础属性与当前帧局部特征。缓存为8×16×384，先将最后一帧的4×4网格平均成384维区域特征；不将候选烟标签复制给16个格点作为像素监督。
- 原版时序logit、轨迹跨度、平均检测置信度和候选数保持相同输入口径。所有新头均能使用相同基础属性，避免把新信息的收益误算为原型机制收益。
- 所有新头使用同一投影维数；原型组以区域特征与烟/背景原型的相似性作分类证据，普通头直接学习对应分类映射。分类融合容量尽量匹配，并如实记录参数量，不假称不同架构参数完全相同。
- 缓存所需历史不足或间隔超限时，所有新方法采用同一官方分数退回策略，单独报告特征覆盖率；不能仅在各自成功提取的样本上计算成绩。若后来补取单帧特征，所有对照同步重建并另记版本。
- 不同时加入残差、年龄衰减、SAHI、新编码器或新轨迹规则。它们保留独立实验，组合放在单模块证据明确之后。

上述共同项已落实在程序中。具体维数、原型数、数值正则、损失权重和预算以`protocol.json`为准；正式运行会记录协议、源码、数据、标签和特征指纹，修改后需新的RunId。

## 4. 分组与消融

| 组 | 方法 | 要隔离的贡献 |
|---|---|---|
| R0 | 冻结原版Pyronear | 当前参考；沿用相同评价，但阈值仍按新验证协议确定 |
| C0 | 相同输入的普通分类头，分类损失 | 控制新增局部特征、训练与重新校准本身 |
| P1 | 每类单原型，分类损失 | 控制改用相似性分类的影响 |
| P2 | 每类多原型，分类损失 | 相对P1检查多个外观中心的价值 |
| P3 | P2＋区域级BES适配 | 检查散度约束的增量 |
| P4 | P2＋PUO适配 | 检查原型更新/多样性机制的增量 |
| P5 | P2＋BES＋PUO适配 | 检查两者组合，作为PSL区域适配的主要候选 |
| C1 | C0＋普通监督对比损失 | 若有必要扩展：判断PSL专门机制是否超过通用表示约束 |

C0、P1至P5及可选C1均已实现。先执行Smoke检查，再做正式多种子比较。C1为扩展对照，不挪用为PSL名称。不得因某个组结果不佳而从最终汇总中静默删除；如因数值失败未完成，记录原因与覆盖范围。

初步考虑较少原型（例如每类2或4个）和小投影，而非直接复制作者每类10原型。原型数、投影维数和损失权重只在train/val选择，并限制搜索规模。无需提前命名为“云、雾、薄烟、浓烟”等子类；当前标签并不支持这些细分，原型是否对应稳定外观要事后验证。

原始BES/PUO基于大量像素特征；区域样本少、同事件相关性高，协方差可能奇异、部分原型可能无样本。实现时检查有效样本数、矩阵条件数、特征值与梯度有限性；需要正则化、降低维数或修改更新时，明确列出与作者方法的差异。代码能运行不等于适配正确。

## 5. 数据安排

按用户提出的修订，新版主对照保留复核合格的原8例并补2例，原Junction和ml-w分别留作待核实与遮挡专项。2026-10-23选定20191005 FIRE / vo-n及20200306 FIRE / ml-s，完整下载77＋81帧，未使用模型成绩选样。新增119条候选标注及新版10例资格已于正式运行前确认；2019序列另确认0分钟极弱、+6～+7分钟相对明显。原实验六原始8/10结果不覆盖。见[最终标注核查](ANNOTATION_CHECK_20261023.md)、[实际下载记录](REPLACEMENTS_20261023.md)、[固定替代清单](replacement_selection.json)及[数据调整方案](DATA_REVISION_PLAN.md)。

1. 现有train/val可用于工程开发与预实验，保留各自角色；样本按事件/片段平衡，限制相邻窗口主导同一批次。SupCon若启用，优先构造不同事件的同类正对，并避免少数事件支配。
2. 训练困难负例从train中挖掘，验证用于选择。原测试sm、buff只作已知失败案例分析，不放入训练后再对原测试声称独立提升。
3. 保留“烟/背景”和“是否属于目标火情”两套信息。Tusil中的非目标烟仍是烟，可用于烟分类正类，但不能算目标首次正确发现。
4. 标签不确定样本从有监督损失中剔除或另行审核，记录数量；不因模型难识别就重标为背景。早期时间不自动等于低浓度。
5. 原测试整体转为诊断集。最终测试使用新事件、隔离站点及连续正常片段；推理前完成资格和目标标签，排查与实验一至六、训练和验证的重叠。正常验证时长也要扩展，否则0.1/小时的阈值选择仍过于粗糙。

最终测试集建立前，可以报告工程与诊断结果，不能宣布独立泛化胜出。替代数据已于2026-10-23下载并独立记录；程序不自动下载更多正常片段或改变现有划分。

## 6. 评价、冻结与通过条件

- 同一组别使用相同数据、采样方式、训练预算及预先约定的种子42/43/44。正式协议已冻结，保留代码版本、特征/标签指纹、参数量、最佳轮次和训练日志。
- 各模型阈值仅从验证集选择，沿用可比较的误报段合并及时间积分定义；参考约束为≤0.1段/摄像头小时及≤1%超阈时间。测试不得重新选阈值，须报告实际是否满足参考值。
- 主表包含合格事件数、检出与漏检、5/10分钟召回、首次正确定位延迟、正常误报段/小时、超阈时间占比和推理开销。另列正确候选跨阈与最高分区域是否正确，避免掩盖区域竞争。
- 延迟同时报告共同检出事件的逐事件配对差值及漏检观察窗口。检出事件中位数仅作补充，不用它替代召回和误报。官方可见起点与人工可见起点分列，主比较不得混用。
- 诊断报告按事件/站点给出结果、原型占用和跨事件分布，检查塌缩或相机记忆。可视化原型代表裁剪仅用于解释，不能凭图给原型强行命名。

期望PSL适配相对C0和P2，在不降低早期事件召回的前提下降低实际误报或取得可复核的延迟收益，且多种子方向一致。若仅在旧诊断集单例有效、只改善候选BCE、仅靠提高阈值降低误报，或无法超过普通分类头，则不认定PSL专门机制得到支持。新鲜度和候选覆盖仍须各自验证。

## 7. 后续阶段

只有区域适配表现出稳定价值、像素掩码和环境条件准备充分后，再单独评估完整PSL分割。若希望研究自己的创新，可考虑早期烟雾原型保护或基于证据可靠性的融合；须先查新、给出明确改动并完成对照，不能把引入既有PSL直接写成原创。

脚本、协议和输出分别位于`scripts/`、`protocol.json`和`outputs/<RunId>/`；单元检查位于`tests/`。实验七的共享标签、资格记录和清单副本在`data/exp007_psl_branch/`，原实验六只读。
